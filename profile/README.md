### LibraryAPI — REST API для библиотеки

Основной проект: REST API для библиотеки на .NET 10 — книги и авторы с фильтрацией, сортировкой и пагинацией, аккаунты сотрудников и обычных пользователей с ролями `admin` / `librarian` / `user`.

- **Аутентификация:** JWT access + refresh с ротацией, в базе только SHA-256-хеш, отзыв токена, BCrypt для паролей.
- **Кэш:** Redis по префиксам `books:` / `authors:`, инвалидация по агрегату, короткие таймауты, fail-open и circuit breaker — при отказе кэша запросы идут в базу, API продолжает работать.
- **Тесты:** 52 юнит-теста сервисов и 24 интеграционных через HTTP и реальный SQL Server в Testcontainers.
- **Запуск:** `docker compose up -d --build` — API, SQL Server 2022 и Redis 7 с healthcheck, миграции и демо-данные применяются автоматически.
- **CI:** GitHub Actions — сборка и тесты на каждый push и pull request.
- **Структура:** шесть проектов — API, Contracts (DTO и валидация), юнит-тесты, интеграционные тесты, два консольных клиента по ролям.

### Дипломная работа GameChat — игровая платформа для текстового общения (минималистичный аналог discord)

Клиент-серверное приложение для текстового общения в реальном времени: регистрация с подтверждением по email, друзья и заявки, личные сообщения со счётчиком непрочитанных, групповые чаты по играм с паролем и лимитом участников, модерация.

- **Архитектура:** два WCF-сервиса. `IService` — запросы «клиент → сервер» (вход, комнаты, друзья), `IService2` — обратный канал: сервер сам вызывает метод на клиенте, когда приходит сообщение. Это push в реальном времени без опроса сервера.
- **Транспорт:** `netTcpBinding`, callback-контракты, хранение онлайн-пользователей вместе с их `OperationContext`.
- **Данные:** SQL Server, ADO.NET (`SqlConnection`, `SqlDataAdapter`, `SqlDataReader`), семь сущностей, развёртывание через `.bacpac`.
- **Клиент:** WinForms — регистрация и вход, добавление в друзья и личные чаты, групповые чаты по играм, их настройка и модерация.
- **Диплом:** защищён на отлично, 2-е место на курсе; в репозитории лежат пояснительная записка и презентация.
- **Ограничения (осознанно оставлены как есть):** SQL собирается конкатенацией, пароли хранятся в открытом виде, нет слоя репозиториев и тестов. Код после защиты не менялся — это честный срез уровня на тот момент.


### ApexBliss — учёт компьютерного клуба

Консольная система: компьютеры, клиенты, игровые сессии, сводка в реальном времени.

- **Доступ к данным:** Dapper и параметризованные запросы — сознательный отказ от ORM, чтобы писать SQL руками и видеть маппинг.
- **Архитектура:** Repository pattern и интерфейсы `IDBComputers`, `IDBClients`, `IDBSessions`; меню не знает про SQL, реализации создаются в точке входа и передаются через конструктор.
- **Транзакции:** старт и завершение сессии атомарно меняют три таблицы (сессия, компьютер, клиент) и откатываются при ошибке.
- **Доменная логика:** модели с `private set`, результат операции — `enum Answer` вместо исключений; ограничение «один клиент — один компьютер» держится на уровне логики, а не UI.
- **Ограничения:** схема создаётся скриптом, миграций нет; тестов нет — проверка ручная.
